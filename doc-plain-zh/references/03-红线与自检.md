# 03 · 红线与自检

本文件定义"什么绝对不能改"和"交付前必须核对什么"。这些是用户"内容真实性不能改变"的直接落点。

---

## 一、绝对不能动的内容（改动即失败）

### 1. 硬事实
- 所有数字：数值、百分比、金额、时间、尺寸、版本号
- 日期与时间表述（"2024 年 3 月"不可写成"去年三月"）
- 人名、机构名、产品名、地名、专有名词（含大小写、中英文形式）
- 引用、公式、代码、字段名、接口名、路径
- 结论性陈述（"实验表明该方法有效"这类判断，可改句式但不可软化/强化）

**示例（禁止）**：
- ❌ "准确率提升 5.2%" → "准确率显著提升"（丢数字）
- ❌ "NVIDIA Jetson Thor" → "英伟达的机器"（术语替换）
- ❌ "2026 年 8 月" → "上个月"（信息丢失）

### 2. 逻辑结构
- 因果、转折、让步、并列、递进关系
- 段落顺序、章节顺序、列表顺序
- 论证的主从关系（谁是论点、谁是论据）

### 3. 语气底线
- 不引入原文没有的态度/立场（原文中性 → 保持中性）
- 不加入幽默、讽刺、情绪
- 不把正式表达改成网络用语

---

## 二、可以改的（本技能的本职）

| 可以改 | 举例 |
|--------|------|
| 句式 | 长句拆短、被动改主动 |
| 用词（同义、更直接） | "予以了全面的评估" → "全面评估了" |
| 冗余成分 | 删"相关/进行/值得注意的是" |
| 语序（不改变信息顺序与逻辑） | 状语后置 |
| 标点（服务于可读性） | 句号替代逗号、加括号展开定语 |

**边界**：改写后不能让人误以为内容变了。如果一处改动会让读者对事实产生不同理解 → 不改。

---

## 三、交付前自检清单（逐项执行）

### 事实核对
- [ ] 全文所有数字与原文逐一比对（可抽样 ≥5 处 + 全部关键数字）
- [ ] 所有专有名词拼写一致（中英文、大小写）
- [ ] 引用、公式、代码块原样复制，一个字符未动

### 逻辑核对
- [ ] 段落/章节顺序与原文一致
- [ ] 连接词含义与原文逻辑吻合（因果未被反转、转折未被抹平）
- [ ] 每处"显性化"的逻辑，原文确有隐含依据

### 内容核对
- [ ] 信息点计数 ≥ 原文（无删减、无合并丢失）
- [ ] 未新增任何事实性内容（补缓冲句除外，且已标注）
- [ ] 未新增比喻、类比、情绪、观点

### 风格核对
- [ ] 通读一遍：是否存在需要回读两遍才能懂的句子（有则继续改）
- [ ] 无网络口语/夸张词/俏皮话
- [ ] 术语未替换成非标准说法
- [ ] 整体仍为书面正式语体（不是聊天体）

## 四、边界案例问答

**Q1：原文有个明显笔误（如"2024 年"写成"2042 年"），能顺手改吗？**
不能。笔误属于"内容真实性"范畴，先**标注提醒用户**，由用户确认后改。你的职责是语言，不是事实纠错（除非用户明确授权）。

**Q2：原文有两处重复表述，能合并吗？**
不能删，但可以**保留信息**地精简措辞。合并 = 删除，会改变信息点数量。确要合并必须向用户说明。

**Q3：术语第一次出现，能加英文括注吗？**
可以，但这是"新增内容"，需标注。默认不加，除非用户要求或文档有这惯例。

**Q4：用户说"顺便帮我改一下那个数据错误"？**
这是明确授权，可以改，但必须在对照表里**单独标注**"事实修正"类别，与语言改写区分开。

**Q5：原文是 AI 味很重的文档，要顺带用 humanizer-zh 吗？**
不要自动做。humanizer-zh 会降正式度、加入个性，与你的默认目标冲突。只在用户明确要求"更有人味"时，作为**第二步**执行，并提示用户其副作用。

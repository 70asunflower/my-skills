# 教程写作：模板、红黑榜与三道门清单

SKILL.md 正文只留判断规则；本文收模板与逐项清单，交付前对照勾选。

## 文档信息头（必填模板）

```markdown
> 文档信息
>
> - 适用读者：…（起点能力，写具体）
> - 前置要求：…（没有就写"无，第 N 章从头讲"）
> - 预计学习时间：通读 X 小时；动手实践 Y
> - 版本基准：YYYY 年 M 月 D 日整理，引用来源见文末
> - 姊妹篇：…（系列文档时，注明结构对齐关系）
```

## 骨架模板：知识类（协议、架构、原理）

1. 初识（一句话定义；三个以内核心卖点；会在哪些场合遇到；与最近似物的设计哲学对比）
2. 背景：为什么需要它（旧方案的真实代价，逐项拆解）
3. 预备知识（读者缺的公共基础，自包含讲清，此处是术语首次解释的重灾区）
4. 核心机制（分层或分模块推进，每节开头先给该节在全局中的位置）
5. 性能：数量级与代际 / 规格表
6. 生态与工具（驱动、中间件、运维命令）
7. 应用场景（真实产品、真实数字）
8. 优点与局限（局限含竞争路线与趋势判断）
9. 与同类技术对比（系列文档共享同一张表）
10. 动手实践路径（无硬件等价物优先；上手顺序命令化，每步给判读要点）
11. 学习路径与资源
12. 术语表（复习索引）
13. 常见问题 FAQ（选读者真实会卡的问题，答案给判读方法而非空话）
14. 参考资料（编号，全部真实可查，一手优先，注明哪些数字出自哪条）
15. 文档说明（AI 辅助声明 + 核验范围 + 版本基准）

## 骨架模板：工具类

0. 开头即最小可用路径：安装 → 跑通 → 看到结果（先有成就感再讲原理）
1. 它解决什么问题（不用它会怎样，给具体症状）
2. 安装与前置（逐条命令 + 各平台差异）
3. 最小示例（逐行注释）
4. 核心概念（跑通之后回头讲为什么）
5. 常用配置与进阶用法
6. 排错（症状 → 根因 → 处置 的表格）
7. FAQ / 术语表 / 参考资料 / 文档说明

## 例子红黑榜

红榜标准（四条同时满足才准入正文）：

1. **真实来源**：真实产品、真实协议、真实数据、真实故障案例。
2. **同构**：例子的结构映射回机制不塌陷；类比只在与机制同构的范围内使用，超出即撤。
3. **有信息增量**：例子本身教了新东西，删掉例子正文会变难懂，而不是删掉无所谓。
4. **标明简化**：与真实情况的差异明说（"实际还有 X，此处略去"）。

黑榜（出现即换）：

- 幼儿园类比硬套技术语义：类比讲完了，读者还是不懂机制本身。
- foo/bar、张三李四式填充：删掉例子，正文毫无损失。
- 玩具数字：用 3 个节点演示需要百节点规模才成立的机制，且不声明简化。
- 口径漂移：例子里的数字、名称与正文其他处不一致。

## 三道门清单（交付前逐项勾）

### 门一 陌生术语扫描

- [ ] 以读者画像的起点通读全文，圈出每个术语的首次出现处
- [ ] 每处首次出现有当场解释或明确章节指针
- [ ] 全文同物同名，无同义词漂移（术语表与正文用词一致）

### 门二 事实抽查

- [ ] 关键数字、年代、版本逐条对照来源清单
- [ ] 检索不到的都标了"约 / 前后 / 未核实"，无编造
- [ ] 确定程度的用词与证据强度一致（可能 ≠ 确定，计划 ≠ 已完成，二手口径已注明）
- [ ] 文档说明块在位（AI 声明 + 核验范围 + 版本基准）

### 门三 图文与格式

- [ ] 每张图被正文引用，编号连续
- [ ] 图内数字、术语、状态色与正文口径一致
- [ ] 标题层级、锚点、表格、代码块完好
- [ ] humanizer-zh 已过一遍

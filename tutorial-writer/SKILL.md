# Tutorial Writer — 初学者知识教程生成

为指定主题产出一份（或一系列）详细完备、事实正确、图文并茂、语言自然的学习文档。流程原型是 RDMA 三网络文档实战（`D:\Project\Zcode\InfiniBand初学者学习文档.md` 等三份，思源在 /AIInfra/RDMA 网络/），每一步都经真实交付验证；风格与深度拿不准时先读原型校准。

## 硬性红线（任何一条不满足即返工）

1. **术语零突然**：术语第一次出现必须当场一句话解释，或明确指路（"见第 N 章"）。**缩写首次出现必须写全拼**：中文术语用"全拼（缩写）"格式，如"远程直接内存访问（RDMA）"；纯外文术语用"缩写（Full Name，中文含义）"，如"PFC（Priority-based Flow Control，按优先级流控）"。此后全文统一只用缩写，不再来回切换。文末术语表只做复习索引，不替代首次解释。判断基准是读者画像的起点，不是作者自己的熟悉度。
2. **禁止前向引用**：正文不得使用尚未讲过的概念。需要前置的概念，要么在大纲里排到更靠前，要么显式给指针。
3. **关键事实必须有来源**：数字、年代、版本、规格、性能指标，要么 ≥2 个独立来源，要么 1 个一手来源（RFC、官方文档、规范、论文）。检索不到就写"约""前后""未核实"，禁止编造；二手统计口径要注明（如"社区统计口径"）。
4. **例子四条标准**（红黑榜见 `references/checklists.md`）：来自真实世界、与被讲机制严格同构、本身有信息增量、标明简化点。幼儿园类比、foo/bar 填充、不声明简化的玩具数字，都是白痴例子，出现即换。
5. **humanizer-zh 不过不交付**；**正文没有引用的图不配**。

## 流程七步

### ① 任务定义

- 定三件事：主题与边界、读者画像（已知什么 / 学到什么算完成 / 投入多少时间）、交付落点（本地 md / 思源 / 两者）。
- 默认自主执行、不设交互确认点，长流程编排开销要最小。仅当读者起点与落点都推断不出时才问一次。
- 用户点名了已验收的旧文档 → 以它为风格与结构基准，先读再写。

### ② 调研与事实核验

- 内建轻量纪律：多源核验、一手优先、编号来源清单落盘（后续直接进参考资料）。重度文献研究才动用 deep-research 技能。
- 实测教训：WebSearch 整批失败时重试单条即可，属瞬时故障；WebFetch 超时就 curl 拉原文到本地再 Read；官方统计页路径先确认含义再引用（如 TOP500 的 osfam 是操作系统族、intrafam 才是互联）。
- 产出：已核验事实列表 + 不确定项列表（后者决定正文里所有"约/前后"的落点）。

### ③ 依赖排序大纲

- 列全部知识点 → 标注谁依赖谁 → 按依赖序排章节。"逻辑通顺"在这里实现：读者永远用旧概念学新概念。
- 骨架模板见 `references/checklists.md`（知识类 / 工具类两套）。文档信息头（适用读者、前置要求、预计时长、版本基准、姊妹篇）是必填项。
- 系列文档约定：章节编号跨份对齐；多主题对比表只维护一份原文，各份复制同文，改表时全部同步；每份自包含（公共前置知识写精要版内置，不写"见另一份文档"）。

### ④ 写作

- 每个知识点过六问：是什么 / 为什么需要它 / 怎么工作 / 何时用 / 何时不用 / 常见误区。
- 数量级感受原则：讲性能必须给数量级（延迟 ns/µs、带宽代际、规模占比），抽象技术不许只用形容词。
- 代码示例逐行注释、真实可跑；工具类教程开头先给"最小可用路径"——先跑起来，再讲原理。
- 动手实验默认找无硬件等价物（如 RDMA 的 rxe/siw 软件实现模式），并如实声明软件实现的性能不代表硬件。
- 写作时即按 humanizer 约束行文：正式技术文体、无铺垫套话、少用"进行+动词"、控制"的"的层叠。终稿仍须走第⑥步的技能，两者不互替。

### ⑤ 配图（调用 svg-diagram-pipeline）

- 先规划后绘制：每份 3–6 张，覆盖总览、结构、流程、对比、实验拓扑中的至少三类；纯数据用表格，不画图。
- 图文互锁：每张图必须被正文引用（"见图 N"或题注呼应），图内数字、术语、状态色与正文口径一致；逐张目检通过才算完成（目检铁律在该技能内）。
- 执行细节全在 svg-diagram-pipeline 内：本地 md 落点用片段 + 批量渲染 + 相对路径引用；思源落点 file[] 上传换 assets 路径。渲染脚本与图源码放成品同级目录，便于迭代。

### ⑥ 语言润色（调用 humanizer-zh）

- 终稿整体过一遍；代码块、路径、表格数据、标题层级按其文件保护规则保持原样。

### ⑦ 交付前三道门 + 交付

- 门一 陌生术语扫描：以读者起点通读全文，每个术语问"读者读到这里时认识它吗"。
- 门二 事实抽查：关键数字逐条对照来源清单；确认没有把"可能"写成"确定"、把"计划"写成"已完成"。
- 门三 图文与格式：图全部被引用、编号连续、标题锚点完好、表格未变形。
- 文末《文档说明》必写：AI 辅助声明、核验范围、版本基准日期。时效衰减是这类文档的宿命，把边界说清就是质量。
- 本地 md 是基准版。思源落点用 siyuan-kernel-ops 的 sy.py：file[] 上传配图（只认 succMap）→ createDocWithMd → exportMdContent 断言图片数与章节 → reloadUI。

## 指针（规则只在属主技能维护）

- 画图机制、渲染命令、目检铁律 → svg-diagram-pipeline
- 语言修改清单与模式分类 → humanizer-zh
- 重度文献研究流程 → deep-research
- 思源 API、端口漂移、索引滞后 → siyuan-kernel-ops
- 骨架模板、例子红黑榜、三道门清单 → `references/checklists.md`

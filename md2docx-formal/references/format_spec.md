# 中文工程论文 / 报告 Word 排版规范（GB/T 7714 顺序编码制）

> 本规范是 `md2docx-formal` 技能的"人读权威约定"。转换器 `scripts/convert_doc.py`
> 是其程序化实现；即使脚本丢失，也可据此手工重建。

## 1. 转换管线（推荐）

```
源 .md  ──convert_doc.py──▶  规范 .docx
                              ├─ verify_superscript.py  (引用上标核验)
                              └─ audit_docx.py           (层级/字体/目录/页眉页脚)
```

- 生成方式：`python-docx`（不要用 `tencent-local-office-edit` 技能——它依赖本机
  Electron 后端的 `editor_sdk`，沙箱内不可用，且手动改字体易破坏中文 `w:eastAsia`）。
- 重转步骤：改源 md → 跑 `convert_doc.py` → 跑 `verify_superscript.py` 确认引用上标无误。

## 2. 页面与基础排版

| 项 | 值 |
|---|---|
| 纸张 | A4（21×29.7cm） |
| 页边距 | 上3 / 下2.5 / 左2.5 / 右2.5 cm |
| 正文 | 宋体 / 小四(12pt) / 1.5 倍行距 / 首行缩进 2 字 |
| 代码、英文等宽 | Consolas（反引号内） |
| 标题 | 黑体；H1=16pt、H2=14pt、H3=12pt、H4=12pt、H5=10.5pt；H1–H3 加粗 |
| 文档主标题(Title) | 黑体 22pt 居中，**不进目录** |

## 2.5 封面设计（标题页）

转换器会识别源 md 开头的 `# 主标题` 及其后的元信息块，渲染为独立封面页：

- **主标题按"——"拆分**：`——` 之前为主标题（28pt 黑体居中），之后为副标题（16pt 黑体居中）；
  若标题无"——"，整行作主标题。页眉与目录仍使用**完整标题文本**。
- **元信息块**（主标题与第一个 `## ` 之间的内容）按以下规则渲染：
  - 识别到 markdown 表格（含 `|` 分隔行与 `|---|` 分隔行）→ 渲染为**真实表格**并居中
    （如"项目属性"表）；**不再**逐行输出原始 `| ... |` 文字（早期 bug 已修）。
  - 非表格的 `**作者**：…` / 版本 / 日期等行 → 居中段落（作者 12pt、版本/日期 10.5pt）。
  - 日期若源中未显式给出，转换器取**系统当前年月**填充（如"2026 年 7 月"）。
- 封面后接**独立摘要页**（含"摘要"/"关键词"），再接目录页（TOC 域），正文从第一篇起排。
- 封面与主副标题字号集中在 `convert_doc.py` 顶部常量区（`TITLE_SIZE` / `SUBTITLE_SIZE` 等），可调。

设计红线：封面元素不得使用 Word 全选改字体；封面不进目录（属 Title 样式）。

## 3. 标题层级映射（按"篇/章/节"语义，非 # 数量）

| Markdown 语义 | Word 样式 |
|---|---|
| `篇` / `附录A–E` / 前置声明(适用对象/数据可信度声明/适用边界声明/**全文结构说明**) | Heading 1（无论源里是 `#` 还是 `##` 深度，按语义判定） |
| `第N章` / 附录直属章节(X.Y) / 第二篇摘要 / **第二篇导读** / `一、二、三、` | Heading 2 |
| 章内小节(2.1…) / 审计项(10.1…) / 缺口项(G1-R…) / 第二篇导读的子项 | Heading 3 |
| 措施/模板/证据条目/缺口总结/… | Heading 4 |
| E-0001 明细 / 器件明细 | Heading 5 |

- **语义优先于 `#` 数量**：例如 v1.4 版本里"篇/附录/前置声明"写在 `##` 级、`第N章` 写在 `###` 级，
  转换器按文字内容（含"篇""附录""第N章""参考文献"等）与当前父级 `CUR_PARENT` 判定，而非简单数 `#`。
  换文档若结构差异大，调单函数 `_heading_style()` 即可。

- **禁止叠加 Word 自动多级编号（numPr=0）**，避免与人工"第N章/2.1"双重编号。
- 目录：TOC 域 `TOC \o "1-3"`，仅 H1–H3 进目录；用户打开后需右键"更新域"。
- 页眉：文档标题（居中，9pt，下边框线）；页脚："第 X 页 / 共 Y 页"（PAGE / NUMPAGES 域）。

## 4. 引用格式（GB/T 7714 顺序编码制）

- 正文、附录中的引用 `[n]` / `[n,m]` / `[n-m]`（含 `[n, 2]`、`[1，2]`）渲染为**上标**（右上角）。
- 文末**参考文献章节**（标题含"参考文献"）内条目序号保持**正体**；
  含参考文献表（首格"编号"）`[1]–[69]` 等全部正体。
- 代码段（反引号）内的 `[n]` 保持原样，**不**转引用、不转上标。
- 章节判定：全局 `IN_REFERENCES` 标志——遇标题文本含"参考文献"置 True，遇下一个
  Heading 1 置 False（覆盖到附录后恢复引用上标）。参考文献标题是 Heading 2 时靠
  "参考文献"子串命中，不依赖标题级别。

## 5. 关键习惯（避免返工）

- **绝不在 Word 里"全选→改字体/字号"**：该操作只改 `w:ascii`/`w:hAnsi`，不改
  `w:eastAsia`，会让中文变默认字体且压平所有字号。改字体一律改 md 源 + 重跑转换器。
- **严格保真**：不得编造、增删内容；引用序号、数据、术语必须与源 md 一致。
- 内容更新后重跑 `convert_doc.py` + 校验即可，不要手工改 docx 排版。

## 6. 正文列表渲染（关键约定）

### 6.1 有序列表

- **渲染方式**：保留源 markdown 的 **字面 "N. " 前缀**，用 `Normal` 段落 + 悬挂缩进呈现。
  悬挂缩进设为 `left_indent=0.63cm / first_line_indent=-0.63cm`，刚好容下最大两位数编号
  "14."，单数编号空隙极小，续行紧贴编号后正文。
- **严禁使用 Word `List Number` 样式**。原因：Word 内置 `List Number` 样式会在同一文档
  的多个独立列表间**续号**——前面的"适用对象"4 条占用 1–4 后，"主要结论"会承接显示
  5–10 而非 1–6。每条列表的编号由源文件字面决定，不存在跨列表续号。
- 转换后全文应 **0 条 `List Number` 段落**。转换器的 `add_list(numbered=True)` 已实现。

### 6.2 无序列表（项目符号）

- 使用 Word 内置 `List Bullet` 样式。
- `_fix_bullet_style()` 在转换后执行两项操作：
  1. 将 `lvlText` 改为 `•`（U+2022，标准小号项目符号）
  2. **同步将 `rFonts` 从 `Symbol` 改为标准字体**（Times New Roman + 宋体）。
     如果只改字符不改字体，`•` 在 Symbol 字体下无字形，会渲染为方框 `□`。
- 转换后 123 条 `List Bullet` 段落全部使用 `•` + 非 Symbol 字体。

### 6.3 校验清单

- `verify_fidelity.py` 的 `LIST_RE` 条掉了有序列表的 `N. ` 前缀后比对文本（列表文本 227 单元
  命中 227）。
- 额外检查：全文 `List Number` 段落数 = 0；bullet 字体全部为非 Symbol；
  16 组有序列表编号均与源文件字面一致。
